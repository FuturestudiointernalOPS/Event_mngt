# WP-19 — CSV and PDF exports

**Wave** 4 · **Parallel-safe** no (shares `modules/reports/` with WP-18)
**Owns** `apps/api/src/modules/reports/` (export slice)
**Depends on** WP-18

## Goal

A staff member with `report:export` can request a registration file, watch its status,
download it once, and receive a clean failure if generation breaks.

## Contract

| Route | Permission | Behaviour |
| --- | --- | --- |
| `POST /workspaces/:slug/events/:eventId/exports` | `report:export` | `202` with a `PENDING` export row |
| `GET /workspaces/:slug/events/:eventId/exports` | `report:read` | the event's exports, newest first |
| `GET /workspaces/:slug/exports/:exportId` | `report:read` | one export and its status |
| `GET /workspaces/:slug/exports/:exportId/download` | `report:export` | the stored bytes, or a stable error |

## Rules

- The row is the job: `PENDING → PROCESSING → COMPLETED | FAILED`. A conditional
  `updateMany` claims it, so two workers cannot both generate it.
- The generated bytes live with the row; the download is a stable snapshot, not a
  re-query. Files expire after seven days; the row remains as history.
- CSV is UTF-8 with a BOM and CRLF for spreadsheet compatibility. PDF uses the standard
  Helvetica font set and is generated without a dependency.
- At most 10 000 rows are rendered; `truncated` says so instead of silently shortening.
- A failure stores a fixed message, never the database error. The real cause is logged
  with the export id.
- The in-process worker is the queue seam. Moving to BullMQ replaces `enqueue` only.
- Every query carries the organisation predicate; another tenant's export is `404`.

## Acceptance (each becomes a test)

1. CSV quotes commas, quotes and newlines, and writes a BOM.
2. The PDF has a valid header, catalog, cross-reference table and page count.
3. A second worker that cannot claim the row does nothing.
4. A completed export downloads; pending is `409 export_not_ready`; expired is
   `410 export_expired`; failed is `422 export_failed`.
5. A generation error marks the row failed without leaking the underlying message.
6. More than 10 000 rows sets `truncated` and keeps the file bounded.

## Integration requests to the pre-flight

- Schema: `ReportExport`, `ExportKind`, `ExportFormat`, `ExportStatus` and the
  `report_exports` table (frozen).
- Contracts: `contracts/reports.ts` export section.
- RLS policy for `report_exports`.

## Out of scope

BullMQ/Redis, S3 upload of generated files, scheduled exports, and exports that span more
than one event.

## Handover

- `report-exports.service.ts` owns request/read/download; `report-export-worker.service.ts`
  owns generation; `report-files.ts` and `report-pdf.ts` are pure and tested.
- Risk: an in-process worker is lost on restart. A row left `PROCESSING` is visible and
  can be re-requested; a stale-claim sweep belongs with the BullMQ move.
